Offline AI — The Honest Architecture

Why running any LLM locally is the wrong answer, and what actually works instead.

The problem with on-device LLMs
🔋

Battery drain

Even a 1B param model sustained inference consumes 8–15% battery per hour of background operation. Android will throttle or kill it.

📱

RAM pressure

1B model = ~600MB RAM. Android aggressively kills background processes above 200MB. Your service gets murdered every 10 minutes.

📦

App size

Smallest usable LLM: 400–800MB download. Users abandon installs above 100MB. You'd lose 60% of users before they even open the app.

💬

Output quality

1–3B models produce generic, repetitive coaching text. After 3 days users notice it's formulaic and disengage. Worse than nothing.

The correct insight: The "intelligent" features users actually need offline — doom loop detection, risk prediction, pattern recognition — don't require an LLM at all. They require smart algorithms + pre-computed templates. The LLM (Claude) is only needed to generate narrative text, which can always be queued for when the device is online.

The actual algorithms — no LLM needed

Algorithm 1 Doom Loop Detector

Runs synchronously when any app-open event is logged. No background service needed — only fires during active use.

function detectDoomLoop(appId: string, events: AppEvent[]): boolean {
  const window = 15 * 60 * 1000 // 15 minutes in ms
  const cutoff = Date.now() - window
  const recent = events.filter(e => e.appId === appId && e.time > cutoff)

  if (recent.length < 5) return false

  const avgDuration = recent.reduce((sum, e) => sum + e.duration, 0) / recent.length
  return avgDuration < 45 // seconds — compulsive open pattern
}

// Called on every app-open log. Takes < 1ms. No background service.
// No battery impact. Works fully offline.

Algorithm 2 Vulnerability Score — Lookup Table

Computed once per week from history, stored as a 24×7 JSON grid. Lookup is O(1) with zero CPU.

// Computed weekly (background, device idle, plugged in)
function buildRiskTable(history: UsageLog[]): RiskTable {
  const table: Record<string, number> = {}

  history.forEach(log => {
    const key = `${log.dayOfWeek}-${log.hour}`
    const exceeded = log.screenTime > log.dailyGoal ? 1 : 0
    table[key] = (table[key] ?? 0) + exceeded
  })

  // Normalize to 0-1 score over 14-day window
  Object.keys(table).forEach(k => table[k] /= 14)
  return table // e.g. {"Sunday-21": 0.85, "Monday-13": 0.6}
}

Algorithm 3 Behavioral Archetype Classifier

6 rule conditions, computed in milliseconds from the weekly summary. No model weights. No training data needed.

function classifyArchetype(stats: WeekStats): Archetype {
  const { eveningRatio, doomLoops, stressCorr, morningRatio, sessionCount } = stats

  if (eveningRatio > 0.45)     return 'Night Scroller'
  if (doomLoops > 8)            return 'Anxiety Checker'
  if (stressCorr > 0.65)        return 'Stress Escapist'
  if (morningRatio > 0.4)       return 'Morning Doomscroller'
  if (sessionCount > 12)        return 'Boredom Tapper'
  return 'Balanced User'
}

// Runs once per week. < 1ms. Result cached in AsyncStorage.
// Feeds directly into Claude's system prompt when online.

API queue — how Claude calls work around connectivity
1

Event fires (session complete, Sunday report, etc.)

App immediately renders the offline template. User sees a real insight instantly. Zero loading state.

2

API job written to local queue

Stored in AsyncStorage: { type, payload, createdAt, retries: 0 }. Survives app close, crash, kill.

3

NetInfo listener fires on reconnect

@react-native-community/netinfo — an event listener, not a polling loop. Zero background CPU. Fires once when network state changes.

4

Queue flushed — Claude called in foreground

Jobs processed in order. If app is open: insight card updates silently (fade transition). If app is closed: result cached for next open. No background service running.

5

Stale job policy

Jobs older than 24h: use template permanently (Claude insight wouldn't be relevant anymore anyway). No retry storm, no memory leak.
